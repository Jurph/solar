## Priority 1: Event Feed / Event Audio Contract

**Goal:** Make query parameter behavior explicit and predictable.

**Tasks:**
- Decide and document the contract for `limit=0`
- Return `400` for negative `limit`

**Definition of done:**
- No Python slicing exceptions can leak through from bad `limit` values
- Tests clearly encode the intended API behavior

### 2. Add tests for cache-vs-file precedence in `event_audio`
**Goal:** Prevent regressions in stale file / cache edge cases.

**Tasks:**
- Add a test for: file exists, cache missing → `200`
- Add a test for: file missing, cache hit → `200`
- Add a test for: file missing, cache miss, event exists → `202`
- Add a test for: event missing → `404`

**Definition of done:**
- The tests make the intended semantics obvious:
  - `404` means missing event row
  - `202` means event exists but audio is unavailable
  - cached audio beats stale/missing file state
